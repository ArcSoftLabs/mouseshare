## Measured facts you must design against (from A0)

- F1. Deleting a mouse-moved event in the session tap does **not** stop the cursor sprite.
  `CGEventGetLocation` on the deleted events follows the sprite. Anchor-relative deltas
  (`InputCapture._moved`) are therefore wrong on macOS.
- F2. `kCGMouseEventDeltaX/Y` on the tapped event are correct integers; most events carry
  (0, 0) because motion is sub-pixel.
- F3. `CGAssociateMouseAndMouseCursorPosition(False)` pins the real cursor, and the delta
  fields keep arriving — but `CGEventGetLocation` on the tapped events keeps integrating
  anyway. While decoupled, the event location is meaningless.
- F4. Posting or warping from inside the tap callback does not disable the tap on macOS
  26.3 (4444 posts at ~900/s, zero timeouts). Posted events carry our PID.
- F5. pynput's darwin `_handler` calls `_handle_message` (which fires `on_move`/`on_click`/
  `on_scroll` using `CGEventGetLocation`) **before** calling `darwin_intercept(event_type,
  event)`. The intercept gets the raw `CGEvent`; it does not get the proxy. pynput keeps
  the tap as a local variable in `_run` — there is **no** `listener._tap`.

## Requirements

### A3 — capture rewrite, macOS branch only
1. Split the darwin intercepts: `_darwin_mouse_intercept(event_type, event)` for the mouse
   listener, `_darwin_keyboard_intercept` for the keyboard listener (keep its
   `_consume_current` handling exactly as is). Both keep the existing rule: not
   suppressing → return the event; injected (`kCGEventSourceUnixProcessID != 0`) → return
   the event; otherwise swallow (return `None`).
2. In the mouse intercept, while suppressing and the event is not injected, for
   `event_type` in {`kCGEventMouseMoved`, `kCGEventLeftMouseDragged`,
   `kCGEventRightMouseDragged`, `kCGEventOtherMouseDragged`}: read
   `kCGMouseEventDeltaX`/`kCGMouseEventDeltaY` with `CGEventGetIntegerValueField`, and if
   `(dx, dy) != (0, 0)` call `self._on_delta(dx, dy)`. Zero deltas produce no callback.
   Clicks and scrolls keep flowing through the existing `on_click`/`on_scroll` callbacks
   (they fire before the intercept) and are swallowed by the intercept as today.
3. `handle_move` on darwin while suppressing is a **no-op** (F1/F3): do not call `_moved`,
   do not touch the anchor. When not suppressing it keeps reporting `on_move(x, y)` for
   edge detection, unchanged. `_moved`, the Windows filter and the Linux grab/warp path are
   not modified.
4. `start_remote` on darwin: park with `Quartz.CGWarpMouseCursorPosition(anchor)` (not the
   pynput position setter — a warp generates no event), **then**
   `Quartz.CGAssociateMouseAndMouseCursorPosition(False)`, then `suppressing = True`.
   Exactly that order. `limit` is accepted and unused on darwin. Windows/Linux keep using
   `self._controller.position = self._anchor` as today.
5. Re-associate on **every** exit path: `stop_remote()` calls
   `CGAssociateMouseAndMouseCursorPosition(True)` on darwin before returning, even if
   `suppressing` was already False (idempotent, must not raise: wrap in try/except and log
   at warning). `stop()` and the watchdog's capture-lost path go through the same helper.
   Register an `atexit` hook in `start()` on darwin that re-associates, because the
   association is session-global state and this app has native aborts on record
   (`mouseshare/macos.py`). Order matters in `HostSession._release`: `stop_remote()` runs
   before `injector.move_to(...)`; the posted absolute move after re-association is what
   resyncs the location — do not change `_release`.
6. Tap-disabled recovery: on `event_type` in {`0xFFFFFFFE` (`kCGEventTapDisabledByTimeout`),
   `0xFFFFFFFF` (`kCGEventTapDisabledByUserInput`)} both intercepts call
   `Quartz.CGEventTapEnable(tap, True)` and return the event. To get `tap`, wrap the
   listener **instance's** `_create_event_tap` when the listener is built on darwin
   (`_start_mouse`/`_start_keyboard`): call the original, store the result on the listener
   (e.g. `listener._ms_tap`), return it. Do not subclass pynput. Keep this small; A0 saw
   zero timeouts, this is belt-and-braces.
7. Keep every `Quartz` import lazy (inside functions), as today; the module must import
   headless on Linux CI. Constants may be read from the `Quartz` module at call time so the
   tests can fake them.
8. Update the stale prose: the module docstring's macOS bullet, the comment in
   `handle_move` ("Untested as a host …"), and `_moved`'s docstring must describe the
   measured behaviour (F1–F4) in the same voice as the surrounding text. Keep all other
   comments and docstrings.

### A2 — tests, `tests/test_capture_macos.py` (new)
Use `monkeypatch.setattr(sys, "platform", "darwin")`, a fake `Quartz` in `sys.modules`
(a `types.SimpleNamespace` with the constants and recording functions), and the
`DarwinListener` fake pattern from `tests/test_capture.py`. Required cases:
- T1. **Drift regression (must fail on the current code):** with suppressing on, the fake
  listener reports `on_move` at positions advancing away from the anchor (e.g. x =
  1281, 1290, 1400, 2100) while the intercept sees events whose delta fields are
  (1,0), (2,0), (0,0), (3,-1). `on_delta` must receive exactly [(1,0), (2,0), (3,-1)] — per
  event, equal to the event's fields, nothing for the zero event, nothing derived from the
  positions.
- T2. Dragged event types (`kCGEventLeftMouseDragged`) yield deltas like moved events.
- T3. Injected event (PID field non-zero) is returned unchanged and yields no delta.
- T4. Not suppressing: `on_move` is reported with absolute positions; the intercept
  returns the event; no delta.
- T5. `start_remote` records `CGWarpMouseCursorPosition(anchor)` then
  `CGAssociateMouseAndMouseCursorPosition(False)` in that order, and the pynput controller
  position was **not** set. `stop_remote`, `stop`, and the watchdog capture-lost path each
  record `CGAssociateMouseAndMouseCursorPosition(True)`; `stop_remote` twice in a row does
  not raise.
- T6. Tap-disabled notification (`event_type = 0xFFFFFFFE`) → `CGEventTapEnable(tap, True)`
  recorded with the tap object the wrapped `_create_event_tap` returned; the event is
  returned, not swallowed.
- T7. The existing `test_mouse_intercept_cannot_consume_pending_keyboard_event` in
  `tests/test_capture.py` passes **unchanged** (its fake `Quartz` has only
  `CGEventGetIntegerValueField` and `kCGEventSourceUnixProcessID`; that is why the keyboard
  intercept must not read mouse constants).
- Also confirm with a one-off run that T1 fails on the pre-change code (git stash or a
  temporary revert) and say so in the report with the failing assertion line.

### A4 — macOS multi-display origin, `mouseshare/monitors.py`
9. screeninfo's osx enumerator returns AppKit frames: bottom-left origin, y up, primary =
   `screens[0]` at (0, 0). pynput/Quartz use top-left origin, y down, same primary. Add a
   pure function `appkit_to_quartz(screens)` (input: screeninfo-shaped objects, output: the
   same shape or plain namespaces) that converts `y_top = primary_h - (y + h)`, x unchanged,
   and apply it in `enumerate_local` only when `sys.platform == "darwin"`. Single display
   is the identity. Windows/Linux coordinates untouched (their negative origins are already
   correct and must stay).
10. Tests in `tests/test_monitors.py`: single primary → identity; a 1920×1080 secondary
    bottom-aligned to the right of a 2560×1440 primary (AppKit y=0 → Quartz y=360); a
    secondary above the primary (AppKit y=1440, h=1080 → Quartz y=−1080); a secondary
    top-aligned to the right (AppKit y=360 → Quartz y=0). `enumerate_local` applies the
    conversion only on darwin (monkeypatch `sys.platform` and `screeninfo.get_monitors`).
