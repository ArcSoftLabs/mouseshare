## Requirements

### Escape gesture (Benjamin's decision: double-tap Ctrl, Cmd on macOS, configurable)
1. While the host is in remote mode (`capture.suppressing`), tapping the escape key twice within `ESCAPE_WINDOW = 0.5` s (press+release, press+release, no other key in between) ends remote mode: `HostSession` must call the same path as a normal edge return — `_release()`, send `leave`, and warp the local cursor to an inset point on the local monitor nearest the modelled peer position (reuse `_inset`; fall back to the anchor monitor centre if no mapping). The two taps themselves must not be forwarded to the peer (they are consumed), and any keys the peer is holding must be released by the `leave` (already the case).
2. The escape key is a setting `escape_key` in `config.Config` with default `"ctrl"` on Windows/Linux and `"cmd"` on macOS. Allowed values: `ctrl`, `cmd`, `alt`, `shift` (both left and right variants count). Persist via `config.save`/`load` like existing fields; keep the v0.1 migration working.
3. Detection lives in `capture.py` in the platform-independent part (the Windows filter and the macOS intercept both already decode keys before forwarding — hook there), driven by a small pure class `EscapeDetector(key, window, clock)` that is unit-tested without pynput (double tap → True; tap/other-key/tap → False; two taps too far apart → False; held key → False).
4. UI: a "Escape key" `<select>` in the settings panel in `index.html` (same `.panel`/`.row` pattern as the rename control), wired via a new `App.set_escape_key(value)` js_api method that validates, saves, pushes state, and applies immediately to a running capture. Show the current gesture in the session status text (e.g. "Double-tap Ctrl to return") while remote.

### Release always re-warps
5. `InputCapture.stop_remote()` today only clears `suppressing`; the real cursor stays parked at the anchor. Make `HostSession._release()` (used by disconnect/teardown too) move the local cursor to a visible inset point on the local monitor it left (anchor monitor), using the injector/controller path that already exists for the edge return, so that a peer death never leaves the cursor at screen centre with no visible reason. Must be safe to call twice.

### Listener-thread death resets state
6. If a pynput listener thread dies (exception or `stop`) while `suppressing`, the capture must clear `suppressing`, and `HostSession` must be told (`on_capture_lost()` → `_release()` + `leave`) so the host is never left with dead capture and `remote=True`. Implement via pynput's listener `join`/`running` observation from a daemon watchdog thread in `InputCapture` (poll every 0.5 s while started), no busy loop. Test with the existing fake listener objects in `tests/test_capture_windows.py`.
