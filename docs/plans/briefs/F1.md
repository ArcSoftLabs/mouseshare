## Requirements

### Protocol (`protocol.py`, cap `"files"`, all optional types)
1. `xfer_offer{id, files:[{name, size, sha256}]}`, `xfer_accept{id}`, `xfer_reject{id, reason}`, `xfer_chunk{id, i, n, data}` (reuse `chunk_payload`/`ChunkAssembler` semantics but **streamed**: chunks are written to disk as they arrive, never accumulated), `xfer_done{id, file_index}`, `xfer_cancel{id}`, `xfer_error{id, reason}`. One offer may carry several files; files are sent sequentially; `i`/`n` are per file. Chunk size 32 KiB before base64; the encoded line must stay under `MAX_LINE - 256` (measure, as the clipboard task learned).
2. Validation on the receiver, before anything touches disk: `name` is a single path component (reject empty, `.`/`..`, any `/` or `\\`, NUL, control chars, Windows reserved names like `CON`, trailing dots/spaces on Windows, length > 255 bytes UTF-8); `size` is a non-negative int ≤ `TRANSFER_MAX = 4 GiB`; `sha256` is 64 hex chars; at most 200 files per offer. Any failure → `xfer_reject{reason}` and nothing written.

### Engine (`mouseshare/transfer.py`)
3. Sender: streams each file from disk in 32 KiB reads (never whole-file), computes SHA-256 while reading (the offer's hash is computed up front in the same streaming way), sends through the peer's outbox, yields to `pos` traffic (do not starve movement: cap in-flight chunks, e.g. at most 8 unacknowledged; receiver acks every 8 chunks with `xfer_ack{id, i}` — add that type), supports cancel from either side.
4. Receiver: destination directory `~/Downloads/MouseShare/` (created 0700; on Windows `%USERPROFILE%\\Downloads\\MouseShare`); collision → `name (2).ext`, `(3)`, … decided at accept time and held open exclusively; writes to `name.part`, verifies SHA-256 on `xfer_done`, then atomic rename; mismatch → delete `.part`, `xfer_error{reason:"integrity"}`; free-space precheck (`shutil.disk_usage`) against the offer's total size + 64 MiB margin → reject with `reason:"space"`; `PermissionError`/`OSError` → `xfer_error` and cleanup; cancel/disconnect mid-transfer → delete the `.part`; never overwrite an existing file.
5. Setting `share_files: bool` (default `True`), cap advertised only when on; inbound offers auto-accepted only from session-phase peers (the trust model: paired + authenticated), otherwise ignored. Inbound offers while off → `xfer_reject{reason:"disabled"}`.
6. Never log file names' full paths or contents; log ids, counts and sizes only. Errors surfaced to the UI carry the bare filename only.
7. State: `state["transfers"]` = list of `{id, direction, peer_name, files:[{name, size, done}], bytes_done, bytes_total, status: offered|active|done|failed|cancelled, error}`; progress publishes are throttled to ≤ 4/s and go through `state.set` (never from a hook callback).

### UI (`index.html`, `app.js`, `style.css`)
8. A drop zone panel "Send files" that accepts OS file drops onto the window (pywebview gives `event.dataTransfer.files[i].pywebviewFullPath`; also accept a click-to-browse via `window.pywebview.api.pick_files()` using `webview.windows[0].create_file_dialog`), then a device picker (connected peers; on a client, only the host) and a Send button; a transfer list with a progress bar per transfer, Cancel button, and success/failure using `#notice`/`#banner`. Keep the existing visual language.
9. `App` js_api: `send_files(device_id, paths)`, `cancel_transfer(id)`, `set_share_files(bool)`, `pick_files()`; `send_files` validates that each path exists, is a regular file, and is readable before offering.
