## Facts you must respect
- pynput's xorg backend captures globally via XRecord and injects via XTest; `Controller.position` works. Its `Listener(suppress=True)` is an **all-or-nothing grab established at listener start**, not a per-event filter — so remote-mode suppression on X11 has to be done with `XGrabPointer`/`XGrabKeyboard` (python-xlib is already a pynput dependency) taken on `start_remote` and released on `stop_remote`.
- Under a grab with `owner_events=False` and the pointer confined... we still need deltas: on X11 the pointer *does* move under a grab, so use the same approach as the macOS rewrite: after each motion event warp back to the anchor with `XWarpPointer` **outside** the event callback (a dedicated thread or via `XTestFakeMotionEvent`), and compute the delta as `position - anchor` only for events that carry a position not equal to the anchor (mirror `_moved`'s existing limit logic). Warp events must be recognised as our own (compare to the anchor / use a serial) so they are not reported.
- On Wayland (`XDG_SESSION_TYPE=wayland` or `WAYLAND_DISPLAY` set without a usable `DISPLAY`), XRecord/XTest only see XWayland clients: **do not claim support**. Detect it and report it in `permissions()` as `{"needed": True, "granted": False, "reason": "wayland"}` with a message "MouseShare needs an X11 session on Linux (log out and choose 'Ubuntu on Xorg')". Capture must refuse to start (`InputCapture.start` raises a clear `RuntimeError`) rather than half-work.
- Today on Linux `capture.py:168/220` fall through with empty kwargs, so "suppressing" forwards input **and** leaks it locally — that silent mis-branch must be gone.

3. `inject.py`: button-name mapping — pynput's xorg `Button` uses `button8/button9`, Windows uses `x1/x2`; map both directions at the wire boundary so a Windows host's `x1` lands as `button8` on Linux and vice versa (extend the existing drop-unknown logic rather than crashing).
