## Requirements
1. **Client send path.** `ClientSession` gets a `send` callable (injected like `HostSession`'s) backed by an `Outbox` on the client side, created in `_become_client` and stopped in `_do_teardown` exactly like the host's. `App._send` keeps working for handshake messages. A client can now send `pong` (P1's heartbeat reply must go through it) and, in later tasks, clipboard/transfer messages. Add `ClientSession.report_edge(x, y)` sending `edge{x,y}` (register `edge` as an optional type in P1's registry; the host ignores it for now — a later task consumes it).
2. **Inbound handling off the reader thread.** Today `_Link._read_loop` calls `on_message` inline, so a slow handler stalls reads and `pos` frames pile up. Introduce a bounded inbound queue per link (`queue.Queue(maxsize=...)`) drained by one daemon worker thread per link; the reader only decodes and enqueues. Backpressure rule: if the queue is full, **drop the oldest `pos`** (never drop non-`pos` messages; if the queue is full of non-`pos`, block the reader — that is the correct backpressure). Handler exceptions are logged (type only, no payload) and do **not** close the link unless they are `ProtocolError`; the existing "unexpected message → teardown" behaviour is unchanged. Teardown must stop the worker and drain nothing further (no late injections after `_do_teardown`).
3. **Ordering guarantee:** messages from one link are handled strictly in order on its worker (needed for `enter`/`pos`/`leave` and for chunked payloads).
4. The existing client-side `_inbox` collapsing for `pos` (`app.py` around `_become_client`/`_inbox`) must be reconciled with the new queue — one mechanism, not two. Keep the `pos` collapsing semantics tested in `tests/test_outbox.py`.

### Tests
- `tests/test_network.py`: a handler that sleeps does not stall a second message's *receipt*; a handler raising `RuntimeError` keeps the link open; `ProtocolError` still closes it.
- `tests/test_app.py`: client can send a message to the host through its outbox (host receives `edge`); after teardown no handler runs for messages that were queued.
- `tests/test_robustness.py`: flood of 10 000 `pos` followed by one `leave` → `leave` is handled, queue never blocks the reader for `pos`.
