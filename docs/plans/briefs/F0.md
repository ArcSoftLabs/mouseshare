## Question to answer, per platform
When the user is dragging files (left button held, OLE/NSDragging session in progress) and the cursor reaches the screen edge where MouseShare would cross, can a MouseShare-owned window receive that drop so the file list becomes known to us, without breaking the user's drag, and then let the cursor cross?

## Windows spike (`tools/dragdrop/win_edge_drop.py`, run with `py.exe`)
1. Create a borderless, topmost, layered (alpha ≈ 1/255 so it is invisible but hit-testable), tool window 24 px wide along the right edge of the primary monitor (use the real geometry from `screeninfo`; the PC has a 100 % primary and a 125 % secondary below — pick the primary's right edge).
2. Register it as a drop target. Two mechanisms, try both and report which works: (a) `DragAcceptFiles(hwnd, True)` + `WM_DROPFILES` with `DragQueryFileW` (simplest; works for shell file drags), (b) `RegisterDragDrop` with a ctypes `IDropTarget` vtable (needed if (a) does not fire for Explorer drags on this Windows version). Use `ctypes`/`ctypes.wintypes` only, `OleInitialize` on the thread that registers.
3. Behaviour: print `DRAGENTER`, `DRAGOVER x,y`, `DROP <n> files: <names>` events with timestamps; on `DragEnter` return `DROPEFFECT_COPY`. Also print whether the window received the drop when the user simply *moves* to the edge while dragging without releasing (it will not — that is the point: we need the user to release at the edge, or to complete the drop on the *remote* side). Document the UX consequence.
4. Then test the alternative that the plan hints at: while the drag is over our edge window, warp the cursor (`SetCursorPos`) to the far side and observe whether Windows cancels the drag (`DragLeave`) or continues it. Print the result.
5. Cap the run at 60 s, exit cleanly, restore nothing (no persistent changes).

## macOS spike (`tools/dragdrop/mac_edge_drop.py`, pyobjc; Benjamin runs it in Terminal)
1. An `NSWindow` of level `NSStatusWindowLevel`, borderless, `alphaValue` 0.01, `ignoresMouseEvents = False`, 24 px along the right edge of the main screen, whose content view registers `NSFilenamesPboardType`/`public.file-url` and implements `draggingEntered_` → `NSDragOperationCopy`, `draggingUpdated_`, `performDragOperation_` printing the file URLs.
2. Same warp experiment with `CGWarpMouseCursorPosition` while the drag is over the window; print whether the drag session survives.
3. Run loop on the main thread, 60 s cap, `RESULT` lines like `tools/mac_tap_probe.py`.
