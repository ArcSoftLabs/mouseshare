## Requirements

### Version negotiation (backward compatible with v2 peers)
1. `protocol.VERSION` becomes 3. `MIN_VERSION = 2`. Every encoded message still carries `"v"`.
2. `LineBuffer`/decoding no longer requires an exact version match: a message whose `v` is an int in `[MIN_VERSION, VERSION]` is accepted; anything else raises `ProtocolError` as today. Each link remembers the peer version from the first decoded message (`link.peer_version`), and the app exposes the negotiated version `min(VERSION, peer_version)` for the active session.
3. A `caps` field (list of strings) is added to `pair_ok` and to the host's `layout` message (host→client) so both sides learn each other's capabilities. Current caps: `["heartbeat"]`. Absent field (v2 peer) means no caps. Store the peer's caps on the App (`self._peer_caps: frozenset`).

### Optional-type tolerance
4. Introduce `protocol.OPTIONAL_TYPES` (initially `{"ping", "pong"}`) — types a peer may send that must be **ignored, not fatal**, when unexpected or unsupported. `_on_message`'s phase table check must drop an optional type silently (debug log with type only) instead of `_teardown("unexpected message")`. Non-optional unknown types stay fatal exactly as today. Add a hook so future tasks can register optional types.

### Chunk helpers (no consumer yet)
5. `protocol.chunk_payload(kind: str, id: str, data: bytes, size=32*1024) -> Iterator[dict]` yielding `{"t": kind, "id": id, "i": index, "n": total, "data": base64}` messages, and `protocol.ChunkAssembler` that accepts those messages, validates `i`/`n`/`id` consistency and a caller-supplied byte cap, and returns the bytes when complete; malformed sequences raise `ProtocolError`. Pure functions, fully unit-tested (ordering, cap exceeded, duplicate index, mismatched `n`).

### Heartbeat
6. Once a session is active and the peer's caps include `"heartbeat"`, each side sends `ping{seq}` every 2.0 s and replies `pong{seq}` to any `ping`. If no message of any kind (not just pong) has been received for 6.0 s, the link is closed with reason `"heartbeat"`, which must flow through the existing disconnect path so the host releases capture and the client releases held keys (the existing `_teardown` does this). Intervals are module constants (`HEARTBEAT_INTERVAL`, `HEARTBEAT_TIMEOUT`) so tests can shrink them. The timer thread must be a daemon, stop on teardown, never raise out, and must not be created for v2 peers. Pings must not be collapsed or delayed by `pos` traffic in `Outbox` (they are not `pos`, so today's collapsing leaves them alone — verify with a test).
7. Do not log message payloads. Log `t` only, as today.
