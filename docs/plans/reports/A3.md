# A3 — macOS delta capture and cursor decoupling

Implemented the H1-confirmed branch from A0. While macOS capture is remote, movement now
comes only from the raw event's integer `kCGMouseEventDeltaX/Y` fields. Callback locations
are ignored because they continue integrating after the cursor sprite is decoupled.
Zero-delta events are swallowed without producing movement. Dragged movement uses the same
path, while clicks and scrolls continue through pynput's callbacks before interception.

The mouse and keyboard intercepts are separate. Both pass events while capture is local,
pass injected events, swallow physical input while remote, and re-enable either disabled
tap notification. Keyboard `_consume_current` handling remains ahead of those rules.

Remote entry now warps the cursor directly through Quartz before decoupling it. Every
remote-exit path performs a best-effort re-association, including repeated calls,
listener-loss recovery, ordinary shutdown, and the registered process-exit hook. The
existing `HostSession._release` order was preserved, so its absolute injected move occurs
after re-association and resynchronises the location.

`appkit_to_quartz` converts screeninfo's macOS frames from AppKit coordinates to Quartz
coordinates with `primary_h - (y + h)`. `enumerate_local` applies it only on Darwin;
Windows and Linux retain their existing origins.

## Darwin call order

`start_remote`: store the integer anchor and limit; reset the escape detector; call
`CGWarpMouseCursorPosition(anchor)`; call
`CGAssociateMouseAndMouseCursorPosition(False)`; set `suppressing = True`.

`stop_remote`: set `suppressing = False`; call
`CGAssociateMouseAndMouseCursorPosition(True)` through a non-raising helper. Repeated calls
perform the association again.

## Tap reference

Immediately after constructing each Darwin listener, its instance
`_create_event_tap` callable is wrapped. The wrapper calls the original, stores its return
value as `listener._ms_tap`, and returns it unchanged. This captures the same tap that
pynput's `_run` otherwise keeps only in a local variable, without subclassing pynput.

## Follow-up: warp-settling delta (live test, 2026-09-04)

Benjamin ran the 3aa6f70 build on the Mac (host) against a Windows client. Windows->Mac
worked; Mac->Windows never crossed — the peer cursor returned to the Mac centre instantly
on every attempt (`biggest step 1277 px` in the debug log, half the Mac screen). Cause: the
macOS delta path in `_darwin_mouse_intercept` applied no sanity clamp, unlike `_moved`. The
first hardware event after `start_remote`'s `CGWarpMouseCursorPosition` carries the warp
displacement (edge to centre) in its `kCGMouseEventDeltaX/Y`, which shoved the modelled peer
cursor back over the boundary. Fix: drop any single-event delta greater than `self._limit`
in the intercept, the same rule `_moved` uses on Windows/X11. Regression test
`test_the_warp_settling_delta_after_a_crossing_is_dropped` fails on the pre-fix intercept.
Green on Linux (370), `py.exe` (369+1 skipped) and the Mac's pyenv 3.13 (370).

Not the fix's concern, observed in the same run: the Windows peer negotiated protocol v2
(`does not authenticate pair_ok (protocol v2)`), so that box is still the packaged v0.2.0
build. It therefore has no escape gesture, which is why double-tap Ctrl on Windows did
nothing. Re-test escape and any v3 feature with the new build on the Windows side too.
