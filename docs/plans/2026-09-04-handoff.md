## How Sol is run (and the problem to route around)

Working invocation (see memory `codex-sol-runner`):

```
cd "<repo>"; export PATH=$HOME/.local/bin:$PATH
codex exec --model gpt-5.6-sol -s workspace-write \
  -c 'sandbox_workspace_write.network_access=true' --skip-git-repo-check \
  -o <out>/<task>.last.md "$(cat docs/plans/briefs/<task>.md)" < /dev/null > <out>/<task>.log 2>&1
```

**Problem, and the route that works:** background Bash jobs (and a Monitor) were killed
from outside the session five times in the 10:xx session. **Verified fix (F1 rework 1 and
2, 30 and 20 minutes each):** write the invocation to a script and launch it fully
detached, then poll for the output file from bounded foreground Bash calls:

```
setsid nohup bash -c 'cd "<repo>" && export PATH=$HOME/.local/bin:$PATH && codex exec ... ' \
  > /dev/null 2>&1 < /dev/null &
```

and detect completion with `until [ -s <task>.last.md ] || ! pgrep -f 'codex exec'; do
sleep 20; done` in a foreground call with a ~9-minute timeout, repeated. Logs reach 2 MB;
read them only with grep/tail. Fallback if that ever dies: foreground `timeout 590 codex
exec ...` and `codex exec resume --last` per call.

Reviewer subagents (Agent tool, fresh context, read-only) were never killed; keep
using them. Review protocol and budget: gate 1 + gate 2, at most two rework rounds, then
the controller decides (Benjamin's instruction: converge fast). Every brief carries a
"Preservation rules" block because Sol once rewrote `app.py` wholesale (memory
`sol-rewrites-need-preservation-rules`); always check `git diff --stat` for net shrink.
